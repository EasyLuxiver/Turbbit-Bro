# STAGE 2 — 完整基础机制

产物：`res://scenes/race.tscn`（主比赛场景）。数值集中在 `scripts/systems/tuning.gd`。

## 目标

把阶段 1 的双角色换人扩成一局完整比赛：氧气、事故分级、六类障碍、加速收益与风险、连击与 SHOWTIME、常驻 HUD。

## 已完成

- 三段判定窗口，兔子滑落与乌龟下沉统一为 0.8 / 2.4 / 3.6 s：
  0–0.8 提示（不滑不沉）、0.8–2.4 开始、2.4–3.6 危险、>3.6 事故。
- 氧气 8 s，三档 5 / 2.5 / 0；水面恢复、空中不耗、换人不回氧、耗尽紧急上浮、SHOWTIME 完成补满。
- 事故分级：硬直 0.8 s（同时减速）、脱壳救援 2.2 s、触礁停机修复 2.0 s、紧急上浮 2.0 s；四类都能恢复并继续比赛。
- 六类障碍接入主场景：水面礁石、低矮横梁、水下暗礁链、水面墙、空中横杆、加速通道；都有预警条和通过动作提示。
- 加速通道 380 px/s：有视觉反馈；加速时兔子滑落时钟 ×1.35，形成收益与风险。
- 连击与 SHOWTIME：只由干净通过计数，3 次触发；自动跳 + 720° 翻滚 + 落地表演；完成补满氧气；SHIFT 可中断且兔子立即从滑落读秒。
- HUD 四角常驻（控制/状态、计时/速度/区域、氧气、连击）+ F1 调试面板 + H 碰撞框。
- 测试中发现的公平性修正：
  - 水面岩石宽度 150 → 90 px。原宽度下起跳可行窗口只有约 57 px（约 0.25 s），几乎只能靠背板。
  - 触礁后冷却 2.5 → 4.0 s。修复 2 s 后只剩 0.5 s，乌龟还停在墙里，必然二次撞击。
  - 连击判定增加 `entered_groups`：必须真正靠近过障碍才具备通过资格，瞬移/跳段不再白拿连击。

## 有趣性自评

1. 新增操作一句话能说清：SHIFT 把控制交给另一个角色，没人控制的那个开始滑落或下沉。
2. “我判断了，然后成了”的时刻：90 秒记录 t≈6–18 s，跳岩石 → 蹲横梁 → 潜暗礁，第 4 次干净通过触发 SHOWTIME（日志 combo 1→2→SHOWTIME，`stage2_showtime.png`）。另一个是触礁修复后约 2 秒内必须下潜穿墙。
3. 错误有可见后果：硬直减速、脱壳救援、停机修复、氧气紧急上浮，HUD 与横幅同步变化，脚本中每次事故都被记录并恢复。
4. 比阶段 1 多的再试理由：SHOWTIME 连段、加速通道的收益/风险、六类障碍的动作对应。

最无聊的 30 秒：`t≈60–91 s`（第 2 圈末到第 3 圈末）。障碍顺序与第 1 圈完全相同，4900–6200 段只剩加速通道和组合障碍，第三遍没有新信息。当前只出现一个阶段，尚未触发“连续两阶段同一处无聊”，但阶段 3 必须换编排或加新障碍。

结论：**有趣**（保留意见：三圈重复、横梁窗口偏紧）。
