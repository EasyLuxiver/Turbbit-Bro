# STAGE 4 · 非对称冲浪板 · 设计结论与最小接入方案

> 制作人指令《Asymmetric Surfboard System》的执行结果。日期 2026-11-11。
> 人工试玩仍为 `NOT TESTED`；本文所有结论来自代码事实 + 灰盒/正式关卡的
> 确定性自动驾驶实测，不代表真实玩家的手感与欢乐度。

## 1. 设计结论

### 1.1 成立的部分

| 指令条款 | 结论 | 依据 |
|---|---|---|
| 兔子站在龟壳上，不是骑在背上 | 成立，已是唯一模型 | 兔子 rect 中心 = 乌龟位置 + (0,−58)，站立/趴下/跳跃全部相对龟壳 |
| 取消手动上下控深 | 成立 | `turtle_controller.gd:_tick_surfboard` 受控时目标恒为 `NEUTRAL_DEPTH=334`，`vertical` 只在氧气耗尽时生效 |
| 受控自动浮回巡航水深 | 成立 | `_vy` 向 `clamp((334−y)×3, −150, +90)` 靠拢，加速度 240，约 0.9 s 从 460 抬回 334 |
| 失控缓慢下沉、重新受控自动上浮 | 成立 | 三段 90 / 110 / 160 px/s（SINK_RAMP 180 起步），受控后立即上浮 |
| 不瞬移、有惯性 | 成立 | 位置由 `_vy` 积分，切人瞬间不清零 |
| SHIFT 不清计时/位移/事故态 | 成立，未改 | 只在受控满 0.5 s 后按 2.5/s 衰减 |
| 起跳必须真的离开龟壳 | 成立 | 旧代码里 `up` 同帧按放导致 `is_action_just_pressed` 永远为 false，已按 `stage4_surfboard.gd` 的正确时序修正 |
| BRO OLLIE（龟壳弹一下） | 可行，未做 | 纯表现层，加在 `_tick_rabbit` 起跳回调里，不新增键、不影响判定 |

### 1.2 代价模型（这一层的数才是平衡的核心）

换人不是免费的，每次换人同时改变四样东西：

1. **被控方**：连续受控 0.5 s 后才按 2.5/s 回计时——从 2.4 回到 0 要 1.46 s。
2. **失控方**：计时按 1/s 增长，3.6 s 判事故。
3. **壳深**：兔子握权时壳按 90→160 px/s 下沉，1.1 s 沉约 90 px；
   乌龟握权时按 150 px/s 上浮。
4. **氧气**：水深 > 334+80=414 才掉，1/s；回到线以上按 3/s 回。
   （原 55 在自动驾驶里被证伪：低梁要趴 2 s，出口 500～690，过梁本身就在抽氧，
   49 s / 70 s 两次把氧气抽空判事故。抬到 80 后整条赛道不再出现氧气事故。）

由此得到一条硬约束：**任何一方连续握权 ≈ 2.1 s 是可持续上限**
（2.1 s 内对方从 0 涨到 2.1，回来 1.1 s 收到 0.6，循环稳态）。
超过 3.0 s 的单一握权段必然在段尾掉崖。

设计里的三段式关卡因此分成两类：

- **兔子层（低岩/低梁/空中杆）**：兔子必须握权 1–2.5 s，龟壳同时下沉 150–250 px。
- **乌龟层（下沉门/暗礁）**：乌龟必须失控 2.5–3.0 s（下沉门全程），
  结束时刻乌龟计时约 2.8，兔子计时约 0.05–0.8（它在门里被控着）。

**下沉门的真正价格不在门上，在门后**：出墙时壳在 600～640、乌龟计时 2.8，
要 1.9 s 才抬回 334，而这三秒里兔子没人管。门后必须有 ≥ 600 px 的净空，
否则兔子会在下一个障碍前摔一次。这是旧数值（水面模型）没有暴露的问题。

**门的成本模型（2026-11-11 第 9～11 轮实测修正）**：兔子握权时乌龟是失控方，
速度会从 240 掉到约 110 px/s。过门要穿墙 100 + 乌龟身位 96 = 196 px，
在 110 px/s 下是 2.2 s，壳按 110～160 px/s 一路沉 ≈ 280 px。于是：

```
出墙深度 ≈ 换人时的壳深 + (提前量 − 0.5 s 意识延迟×速度) × 沉速
```

固定提前量两头都翻过车：提前 130 px 时门 2 入墙 y=349（墙底 334，乌龟顶
321 → 撞墙），提前 220 px 时门 4 出墙 733（暗礁判 740）。**换人点必须按
壳深自适应**：壳浅（<420）提前 220 px 换，靠提前量沉出 40～60 px；
壳深（≥420）拖到墙前 60 px 再换，否则出口必过 700。门前准备固定三段：
乌龟压乌龟计时到 0 → 兔子 0.9 s 压兔子计时 → 乌龟抬壳（兔子计时逼近
3.6 时插 0.7 s 兔子段回烧）。

**而且门前的价格同样高**：门要求“带着巡航水深进墙”，壳在 460 进墙就会在出口
沉到 700（浮力掉头还要再沉 50 px）→ 直接判 `TURTLE_REEF`。所以门前必须留
≥ 700 px 给乌龟整段抬壳，这比门本身的 200 px 还长。

实测可持续节拍（自动驾驶）：**乌龟段 1.2 s / 兔子段 0.9 s**，壳在 334～424 之间摆动。
兔子段收回到 1.1 s 会把平均深度抬到 450～490（每段白沉 120 px），下沉门必挂；
收到 1.6 s 才稳。这条是 GDD 数值表里没有的——它只由“兔子握权=壳下沉”推出。

### 1.3 与旧操作的冲突核对（指令要求显式检查）

| 旧规则 | 新规则 | 结论 |
|---|---|---|
| 兔子跳起后切乌龟下潜，用下潜躲低岩 | 切到乌龟=上浮 | 冲突。低岩现在**只能跳**：切乌龟会让壳浮起来、兔子站得更高，撞得更实。低岩的教学文案必须删除「或者潜过去」 |
| 按住下潜穿过长墙 | 切兔子让壳自己沉 | 语义变了但操作序列保留（换人 + 等），只是不需要按住任何键 |
| 下潜是万能解 | 只有下沉门需要潜 | 水下暗礁在 620–770，正常巡航深度完全碰不到，下潜对它是死解 |
| 氧气靠手动上浮救 | 换回乌龟自动上浮 | 旧提示「准备上浮 / 立刻上浮」必须改成「换回乌龟」 |

## 2. 状态转移表（意识 × 乌龟运动 × 兔子运动）

| 意识 | 乌龟 | 兔子 | 结果 |
|---|---|---|---|
| 龟受控 | 浮力回 334、速度回 base、计时衰减 | 计时 +1/s、壳载着它走 | 唯一的“安全”状态 |
| 兔受控（龟壳上，RIDING） | 计时 +1/s、按段下沉 | 速度/动作可控、计时衰减 | 兔子层的正常状态；可持续 ≤ 2.1 s |
| 兔受控（CROUCHING） | 同上，下沉更快（持续时间长） | 趴下 rect 低 32 px | 低梁；梁一过必须立刻交回 |
| 兔离壳（AIRBORNE） | `hold_depth=true` 冻结深度，计时照走 | 抛物线 1.244 s / 174 px | 落地自动吸附；冻结避免“跳一次必摔” |
| 兔离壳漂浮（落地失败） | 计时 +1/s、下沉 | 落水 → RABBIT_WATER | 事故；接人窗口 dx≤120、dy −60~90 |
| 龟事故 | 修复 2.0 s + 冷却 4.0 s | 强制接管 | 事故恢复 |
| 兔事故 | 计时清零、壳被扶正 | 救援 2.2 s | 事故恢复 |
| 氧气耗尽 | 强制上浮（忽略玩家） | PASSED_OUT 2.0 s | 事故恢复 |

## 3. 最小接入方案（不新增键、不新增模式、不改赛道）

已完成：

1. `Tuning.SURFBOARD_PHYSICS = true`，`NEUTRAL_DEPTH=334`，世界整体下移 34 px
   （`WORLD_Y_SHIFT`），障碍几何与旧验证保持相对关系。
2. `turtle_controller.gd` 增加 `_tick_surfboard`（浮力 / 三段下沉 / `hold_depth`），
   删除受控时的上下输入。
3. `is_at_surface()` 改为 `y ≤ 334+120`；`OXYGEN_DEPTH_MARGIN=80`。
4. `race.gd` 在兔子滞空时置 `hold_depth`；自动驾驶按新模型重写动作时序。

待做：

5. 教学文案去「下潜」（locale + level_data 的 EN 串同步改）。**已完成**
   （2026-11-11）：JUMP OVER / CROUCH DOWN / STAY HIGH / TAKE THE RABBIT /
   DON'T JUMP，旧「准备上浮 / 立刻上浮 / 按住下潜」已无残留。
6. 灰盒 A–F 在同一次运行里出改前/改后对照。**已完成**，另加 G 臂：
   乌龟受控时按住 up/down 各 1 s——旧模型 down 下潜 183 px，新模型 dy=0。
7. 开局/事故恢复的高度统一到巡航水深。**已完成**（2026-11-11）：
   开局不再从旧水线 300 浮到 334；氧气紧急上浮与乌龟修理后的落点也从
   `SURFACE_Y` 改成 `surface_ref()`，避免恢复瞬间又在水面之上再落一次。

## 4. 尚未验证 / 风险

- 真实玩家手感：`NOT TESTED`。本文所有“通过”都是确定性自动驾驶跑出来的，
  自动驾驶不会犯玩家的错，也不会感到无聊。
- 下沉门后净空：正式关卡 9 个门里，门后到下一个障碍 < 600 px 的有若干处，
  自动驾驶靠抢兔子段补回来；真人能否做到未验证。
- 深壳可以让兔子“从岩石下面漂过去”（壳深 > 约 340 时兔子 rect 低于岩底）——
  属于设计漏洞，是否要堵需要制作人决定（堵法：兔子 rect 低于水面 20 px 判落水）。
