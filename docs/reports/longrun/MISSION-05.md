## B. 第一阶段：修真实 BUG（最高优先级）

### B1 接应成功却仍然判罚
兔子落水 → SHIFT → 乌龟下潜 → 接到兔子 → 回壳。检查事故状态是否残留、接应成功事件是否被事故逻辑覆盖、
状态更新顺序、延迟碰撞/旧事故事件、HUD/记录/结算一致性。
要求：成功后正确结束落水事故；接应过程真实碰撞仍生效（不是无敌）；不抹掉接应前独立事故；一次事故不重复登记；
成功与失败结果清晰不同。建立正式回归测试。

### B2 双角色碰撞判定错误
乌龟下潜解法的障碍：控制兔子时两角色都撞了，却只记兔子、乌龟只被浪冲开。
要求：单兔/单龟/双撞/先后撞同障碍/浪涌干扰五种回归；非受控角色也必须参与碰撞判定；浪涌/击退不能替代碰撞记录；
不同障碍不错误合并；同次事故不重复叠加。

### B3 BRO DIVE 难以针对障碍成功
扫描全部 BRO DIVE 障碍，选最典型 3 组。逐组分析碰撞范围、可见预警、起跳位置/时间、SHIFT 与下潜时机、
双方轨迹、有效窗口、空间余量。目标：提前理解适用、合理时机稳定完成、窗口不依赖毫秒、
不靠缩小碰撞体伪造、不让普通动作全失效、失败可解释。每组 ≥5 次标准时机重复验证。

## C. 第二阶段：双角色引导条与动作信息（灰盒，必须接入正式 HUD）

C1 两个紧凑状态区：
- 兔子：是否受控 / 当前动作 / 准备跳或空中 / 落水待接应 / 可用协作机会。
- 乌龟：是否受控 / 当前动作 / 巡航·下潜·失衡·接应 / 注意到食物 / 可用协作机会。
不要持续消耗的惩罚倒计时，不要持续闪烁，不要复杂文字。

C2 时机提示：仅有效预警范围内；说明当前适合 BRO DIVE / BRO OLLIE；能看到准备状态与有效时机；
不遮挡赛道与操作区；错过窗口明确结束。

C3 验收：双向控制状态正确、落水与接应状态更新、恢复正确、提示时机正确、中英文不溢出。
必须接入 `race.tscn` 与正式 HUD 更新。

## D. 第三阶段：SHIFT 正向体验

D1 角色互补：兔子快跳/下蹲/空中/平衡、活泼得意调皮但不持续危险；乌龟巡航/下潜/承载/接应、对食物有兴趣、
未受控可有性格但不持续制造事故。差异要体现在玩法。

D2 三种正向切换：障碍协作（打出漂亮连招）、食物互动（切换亲手喂、短暂加速奖励）、救援互动（主动追接、重聚反馈）。
不切换：可错过奖励与高光，不额外惩罚、不持续扣分、不逼迫频繁切换、不双角色同时不可挽救。

D3 神游：沿用四态，不增状态。改善个性、可读性、制造笑料而非负担、留反应时间。只有真实操作失误才出事故。

## E. 第四阶段：动态障碍与节奏

E1 海鸟重做：巡航/观察 → 攻击前摇 → 有节奏俯冲或横扫 → 恢复；轨迹与碰撞一致；可从前摇判断威胁与窗口。
E2 新增三个原型（灰盒几何，接入正式赛道，各先一组样板）：
1. 周期运动型（上下/前后规律移动，考通过时机）
2. 扫掠/追逐型（明确预警后改变危险区）
3. 环境变化型（水流/浪涌/浮动物改变安全空间）
每种运动规律不同、有可读预警与恢复、留反应时间、不偷袭、有基础解法、可存在配合更优解。

E3 三区节奏：Sunny Coast / Coral Chaos / Muscle Mayhem 各自检查静动态比例、组合重复、空跑、连续高压、恢复段、
玩法升级。优先调整现有内容与顺序，不扩张地图。

## F. 第五阶段：GDD 复核与小步优化

读完整 GDD，以玩家视角自评 10 问（理解关系、何时值得 SHIFT、主动切换意愿、躲避直观、熟练提升空间、
动态障碍节奏、失败有趣可恢复、空跑重复、三区差异、总体目标）。
每个问题按循环执行：发现 → 确认原因 → 小范围修改 → 接入正式流程 → 实际运行 → 回归 → 重新自评。
不得只交建议报告或测试组件。
