### 1.1 叙事节拍

海边 → 发现电击蛋糕 → 一起吃 → 触电 → 意识连上 → 演示一次 SHIFT → 进赛道。

### 1.2 逐镜表（总 6.6 s）

| # | 时间 | 画面（正式需求） | 动作 / 镜头 | 占位实现（本轮允许） | 音效需求（冻结） |
|---|---|---|---|---|---|
| 1 | 0.0–1.2 s | 黄昏海边，龟壳浪板斜插在沙里，龟兔并排坐着；远处三个浪头 | 横移镜头由左向右，速度恒定；无对白 | `ColorRect` 三段色带（天/海/沙）+ `Label` “SEASIDE / 海边” | 海浪底噪、远处海鸥 |
| 2 | 1.2–2.2 s | 沙里露出一块奶油蛋糕，表面有蓝色电弧跳动 | 镜头推近到蛋糕；电弧 3 次 | 黄色 `Panel` 方块 + 文字 `CAKE ⚡` | 电弧“滋”声（短，3 次） |

### 1.3 跳过与流程

- 任意时刻 `Enter` / `Space` / `Esc`：立即停播、释放 Intro 节点、`GameManager.start_race()`。
- 自然播完（≥6.6 s）：同一入口进赛道；8.0 s 仍未结束视为超时，强制进入。
- 重复按键不得触发两次 `start_race()`（跳过锁 + 只允许一次）。
- Intro 只在点击主菜单 `START` 后播放；`--autoplay` / 测试入口直接进赛道，不播 Intro。
- Intro 播放中 `GameState` 保持 `MENU`；不消耗氧气、不推进 BRO BRAIN、不计事故。

### 1.4 验收方式（将来实现时）

- 录屏或逐镜截图 6 张，时间戳与表一致；跳过路径与自然结束路径各跑一次；
- 日志打印 `INTRO shot=N t=...`、`INTRO skip key=Enter t=...`、`INTRO done`；
- 断言：进入赛道后 `shift_count=0`、`oxygen=OXYGEN_MAX`、`accidents=0`。

## 2. Pause Screen 分镜

### 2.1 版式（1600×900 设计基准，沿用现有面板）

```
┌──────────────────────────────────────────────┐
│  已暂停 / PAUSED                              │
│                                              │

│   └──────────────┘      [继续游戏]            │
```

- 左侧插画区约占 38% 宽；右侧主句 + 三个按钮沿用现有 `pause_menu.gd`。
- 主句 `Take a breath, bro.` 是**唯一**新增固定文案；中文用 `喘口气吧，兄弟。`
- 现有暂停菜单的 `ESC / R / M` 快捷键不变；语言切换原地重建不变。
- 暂停仍是现有 `GameState.PAUSED`：世界停止、无计时、无输入惩罚。

### 2.2 插画与动画需求（正式美术）

| 元素 | 静态需求 | 动画需求（循环） |
|---|---|---|
| 兔子 | 前爪撑桌、一手托脸，看向玩家；占插画区高度 70% | 呼吸 2.4 s 一循环（胸廓 ±1.5%）；眨眼 3–5 s 随机；耳朵偶尔抖一下（8 s 一次） |
| 桌子 | 木桌一角，与兔子前爪接触点固定 | 无 |
| 乌龟 | 在兔子右后侧，趴在桌沿休息，身旁半块蛋糕 | 呼吸 3.2 s 一循环；每 6 s 探头啃一口蛋糕，2 s 复位 |
| 背景 | 深色不抢字；沿用现有 68% 黑色遮罩 | 无 |
| 文字 | 主句 26 设计 px（1280×720 下 20.8 实际）；按钮沿用 18 设计 px | 进入时 0.15 s 淡入；无弹跳 |

### 2.3 占位方案（本轮允许，不用素材）

- 插画区：一个 `PanelContainer`（深绿底）+ 两行 `Label`：
  `RABBIT · leaning on table, hand on cheek` / `TURTLE · resting, nibbling cake`；
- 主句直接放 `Label`，中英随语言切换；
- 不新增任何图片、字体、图标；布局在 1280×720 下不得截断（沿用 Phase U 的最小字号检查）。

### 2.4 与玩法的边界

- 暂停不触发 `shift_shocked`、不消耗氧气、不推进 BRO BRAIN；
- 暂停界面的动画（呼吸/眨眼）不得使用 `Engine.time_scale` 或暂停世界；
  它们只允许在 `PROCESS_MODE_ALWAYS` 的 UI 层自走，世界仍冻结；
- 若将来加入“暂停时乌龟吃东西”，只做演出，不改 `snack` 的实际加速与计分。

## 3. SHIFT 电击：只保留事件接口

### 3.1 接口

```gdscript
# game_manager.gd
signal shift_shocked(from_who: String, to_who: String)
```

**已落地**（2026-11-12）：信号在 `game_manager.gd` 声明，`toggle_control()` 里
`current_control` 更新后同步 `emit`；无任何订阅者、无视觉、无冷却。
`stage4_shift_graybox` 新增断言并实测：一次换人 `events=1`、`same_frame=true`、
`from/to = turtle→rabbit`；`set_control()` 追加 0 发（`direct_events=0`）。

- 触发点：`toggle_control()` 真正完成切换的那一帧（`current_control` 已更新、`shift_count` 已加）。
- Intro 演示、正式游戏中的 SHIFT 表现、将来的电弧/白闪，全部**订阅**这个信号。
- 订阅者只许播放表现；不得修改 `current_control`、不得阻塞输入、不得写氧气/评分/事故。
- 不新增第二个 SHIFT 入口；`set_control()`（脚本/救援用）不发该信号，避免把“程序换人”演成玩家电击。

### 3.2 明确不做

- 不加输入延迟（信号同步发出，不等待任何 Tween/动画）；
- 不加冷却、不加惩罚、不扣氧气；
- 不在本轮实现电击视觉（正式美术/动画后续接入）。

### 3.3 将来验收

- 一次 SHIFT：`shift_shocked` 恰好 1 次，前后 `from/to` 正确；
- 连续 10 次快速 SHIFT：信号 10 次、`shift_count` 10 次、无输入丢失（沿用
  `stage4_shift_graybox` 的“无输入锁”断言）；
- 带视觉订阅时，按下 SHIFT 到 `current_control` 改变的帧数差 = 0。
