# TBB-EXPERIENCE-REFINE-06 补充设计决策（制作人原文，2026-11-13）

> 本文件是制作人追加的补充指令，取代 REFINE-06 原文中“动态平衡只做轻压力、
> 伙伴自动进入低风险跟随”的表述。原则：**保留压力、提高公平性，不取消失控。**

## 双角色动态平衡：保留压力，优化公平性

制作人进一步确认：

**动态平衡不是应该被弱化或取消的负担，而是 Turbbit Bro! 的核心 SHIFT 机制之一。**

参考《胡闹厨房》的压力组织方式，保留双角色之间的注意力分配、状态维护和主动切换决策。

### 1. 核心原则

玩家控制一个角色时，另一个角色仍然会逐渐产生动态变化。

玩家需要根据当前障碍、伙伴状态和接下来的操作窗口，决定何时 SHIFT。

切换应当具有真实意义：

- 及时切换，可以恢复伙伴状态。
- 延迟切换，会让伙伴逐渐失控。
- 合理安排切换顺序，可以维持两人的行动能力。
- 熟练玩家可以通过规划减少失误并完成连续操作。

不得把动态平衡改成完全无风险的自动跟随系统。

### 2. 不取消失控，而是建立合理的压力边界

沿用已有动态平衡及四个 Daydream 状态，不增加新的状态等级。

重点调节：

- 失控积累速度。
- 不同状态对实际移动和操作的影响。
- 控制后恢复速度。
- 最高失控状态的实际后果。
- 不同障碍组合之间的距离和节奏。

不允许单纯通过大幅降低失控速度，让系统失去存在意义。

### 3. 连续专属障碍的处理

保留连续需要同一角色操作时，另一个角色逐渐失控的压力。

但必须保证：

- 玩家能提前看出伙伴状态。
- 伙伴状态变化具有可理解的阶段反馈。
- 玩家有机会判断是否继续当前操作。
- 不允许出现没有任何合理操作窗口的必败组合。
- 可以产生风险，但风险必须来自玩家能够理解的选择，而不是隐藏计时器或判定错误。

不要自动清除失控状态，也不要为了保护玩家而让伙伴完全免受影响。

### 4. 状态反馈必须明显

兔子和乌龟分别显示自己的状态。

不能继续使用无法分辨角色归属的两个小问号。

要求：

- 明确角色图形与名称。
- 明确当前控制对象。
- 清楚显示伙伴正在走神、摇晃或失衡。
- 状态恶化时反馈逐步增强。
- SHIFT 恢复状态时有明显反馈。

玩家应该能够在不阅读说明文字的情况下判断哪个角色需要关注。

### 5. 参数测试与制作人调参支持

建立可重复的动态平衡测试场景，覆盖：

- 连续兔子专属障碍。
- 连续乌龟专属障碍。
- 两角色交替障碍。
- 伙伴失控期间执行组合动作。
- 高压力段落后的恢复路段。

记录每组测试的：

- 失控状态变化时间。
- 当前控制对象。
- SHIFT 时间与恢复时间。
- 进入障碍时双方状态。
- 碰撞与失误原因。
- 是否存在无合理解法的障碍组合。

每轮只调整少量相关参数，保留修改前后的对照结果。

### 6. 验收标准

不是要求玩家完全没有压力，而是要求：

1. 玩家能感知伙伴状态正在恶化。
2. 玩家能够理解何时切换比较有利。
3. 不切换确实会产生一定代价。
4. 及时切换具有实际收益。
5. 玩家失误后能理解自己错在哪里。
6. 连续障碍不会形成无解的死亡链。
7. 动态平衡能够强化 SHIFT，而不是让玩家厌恶 SHIFT。

**最终目标：保留双角色动态平衡带来的紧张感，让玩家享受在兔子和乌龟之间分配注意力、判断时机和维持搭档状态的过程。**

## 对已排优先级的影响（执行记录）

- P0（碰撞/联合判罚）不变。
- P1（双角色状态条）目标改为：**明确归属 + 可读恶化阶段**，不做“无风险跟随提示”。
- P3（鲨鱼)、P4（食物）、P5（喜剧反馈）不变。
- P6 新增矩阵：连续兔子专属 / 连续乌龟专属 / 交替 / 伙伴失控中做组合 / 高压力后恢复段，
  并记录失控时间、控制对象、SHIFT 与恢复时间、进障碍时双方状态、失误原因、
  是否存在无解组合。
- 参数调整必须小步、前后对照；不得用“整体大幅降速”换平静。
