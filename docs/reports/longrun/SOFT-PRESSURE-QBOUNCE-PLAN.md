# 走神度 + Q 弹碰撞规划书

> **状态：待制作人审阅；审阅通过前不改玩法代码。**
> 已吸收制作人《双身体走神与唤醒机制设计案》。
> 背景：兔子和乌龟吃了大表哥的电击蛋糕，一个意识、两个身体；切人就是电一下。

## 1. 定位

- **机制名：走神度**，不是“惩罚条”。
- **核心交互：走神 → 切换唤醒 → 持续控制恢复。**
- **核心体验：喜剧表现 + 轻微持续压力。**
- 让玩家自然关注两个身体，主动想切换，而不是被计时器逼着切。
- 不是第二套 AI，不是角色失控系统，不是新的惩罚计时器。

## 2. 当前代码事实

- **乌龟弹回**：`_apply_bounce()` 现在是撞上后直接 `x -= 140 px`、速度归零、
  0.8 s 冷却；同组后续不重复扣分，连续 6 次 `BONK_OUT`。
  `stage45_bounce_recovery` PASS；问题是“瞬移感”，不是碰撞感。
- **旧 MISCHIEF**：失误后 7 s 抱怨窗口、1.2 s 反应、0.65 s 预兆，
  然后拽绳/电击；是失误驱动的惩罚事件。
- 鲨鱼看台已暂时移除；`stage21` 断言 `no_stands` PASS。

## 3. 走神度核心规则

兔子和乌龟各自拥有独立走神度。

| 情况 | 走神度变化 |
|---|---|
| 当前未被控制 | 持续增长 |
| 切换到该身体 | 立即停止增长 |
| 持续控制该身体 | 缓慢下降 |
| 再次切走 | 从当前数值继续增长，不重置 |
| 完成一次耍宝动作 | 大幅回落，进入短暂恢复 |

**切换角色不会瞬间清空走神度。** 切换只代表唤醒开始，持续控制才逐渐恢复；
恢复速度明显慢于增长速度，避免“切一下 → 清零 → 马上切回”的机械操作。
不增加 SHIFT 冷却，不限制正常切换。

## 4. 阶段

| 阶段 | 建议区间 | 表现 | 玩法影响 |
|---|---:|---|---|
| 清醒 | 0–40% | 正常活动 | 无 |
| 走神 | 40–70% | 打哈欠、发呆、眼神飘忽、Zzz | 无 |
| 耍宝前 | 70–100% | 伸懒腰、东张西望、偷看零食、跟海鸥挥手 | 无 |
| 耍宝事件 | 满值 | 0.65 s 预兆 → 预设动作 | 轻微后果 |

**未满之前不允许影响速度、碰撞、氧气、位置或输入。**

## 5. 唤醒与恢复

玩家切换到走神身体时：

1. 走神度停止增长；
2. 角色出现短暂电击唤醒反馈；
3. 持续控制该身体，走神度缓慢下降；
4. 玩家可以继续控制，也可以随时切走；
5. 切走后重新增长，但不重置。

玩家不需要频繁切换；可以根据障碍和操作决定唤醒时机。
两个身体的状态分别管理，互不覆盖。

## 6. 满值耍宝事件

1. 约 0.65 s 预兆；
2. 预兆期间切到该身体 → 取消事件，开始唤醒恢复；
3. 没切 → 完成预设动作；
4. 动作结束后走神度大幅回落，进入短暂恢复；
5. 不允许事件连续立即触发。

**后果只取一种：**
- 轻微连击损失；或
- ≤0.5 s 极短暂减速。

**禁止：**
- 直接造成事故；
- 扣除氧气；
- 强制切换角色；
- 锁定玩家输入；
- 改变碰撞判定；
- 让角色自行撞上障碍。

## 7. 动作池：兔子和乌龟各两个

| 角色 | 动作 | 类型 | 表现 | 玩法影响 |
|---|---|---|---|---|
| 兔子 | **打哈欠** | 走神/耍宝前 | 张嘴、伸懒腰、Zzz | 无 |
| 兔子 | **偷看零食** | 满值耍宝 | 偷偷张望、伸手想拿 | 轻微掉连击，不扣氧、不撞 |
| 乌龟 | **发呆** | 走神/耍宝前 | 眼神飘忽、短暂愣神 | 无 |
| 乌龟 | **缩壳/抱膝** | 满值耍宝 | 乌龟缩壳、兔子抱膝 | ≤0.5 s 小减速 |

- 不加入“偷吃海藻获得氧气/分数”的正收益，避免玩家主动刷事件；
- 大部分动作纯视觉喜剧；
- 不加新攻击/技能；
- 不改变逻辑位置、碰撞体；
- 不通过动作制造新的障碍解法。
- 后续候选（本轮不做）：跟海鸥挥手、叉腰得意、说梦话、惊醒抽动。

## 8. 压力调试

先做三档实验，不凭感觉定：

| 档位 | 0 → 满值 | 预期 |
|---|---:|---|
| 轻压力 | 18–22 s | 更偏角色喜剧 |
| 中压力 | 14–17 s | 喜剧与持续关注平衡 |
| 强压力 | 10–13 s | 状态明显，可能烦躁 |

**从中压力档开始测试**，不视作最终值。
Z1/Z2/Z3 暂时相同基础速度，不直接让 Z3 更快；区域差异先通过动作选择和节奏体现。

必须记录：

- 两个身体各自走神度变化；
- 玩家主动切到走神身体的次数；
- 切换后持续控制时间；
- 走神事件触发次数；
- 预兆期间取消次数；
- 自然完成耍宝次数；
- 连击损失/减速次数；
- 是否与障碍、救援、鲨群冲突。

自动驾驶数据只用于规则/稳定性，不代替真人体验结论。

## 9. 替换旧 MISCHIEF

新机制正式确认后，**替换**旧 MISCHIEF 的抱怨、拽绳、电击事件；两套不得并行。

保留：事故、氧气、救援、鲨群、正常切换与障碍操作。

## 10. Q 弹碰撞

### 10.1 一套动作

1. **接触**：壳压扁（横向 1.25、纵向 0.75），兔子前倾、耳朵滞后；
2. **弹开**：ease-out-back，后退 160–200 px，0.35–0.45 s；
3. **过冲**：退过头 10–15%，再拉回；
4. **回弹**：壳 scale 2–3 次阻尼摆动（1.25/0.75 → 0.9/1.1 → 1.0）；
5. **余震**：镜头 2–3 px、水面涟漪、两条橡皮筋弧线、`BOING!`；
6. **连续撞**：囧脸和晃动逐级加大，第 6 次仍 `BONK_OUT`。

### 10.2 实现

- 碰撞判定不变；位置用弹簧/阻尼，不直接 `x -= 140`；
- 画法层单独做 squash/stretch 和阻尼摆动，不碰碰撞体；
- 先做视觉弹簧：位置仍由现有逻辑决定，画法加 offset/scale；
- 不够再改真实弹簧；做卡通物理，不做真实物理。

### 10.3 可调参数

| 参数 | 默认 | 轻 | 夸张 |
|---|---:|---:|---:|
| 后退距离 | 180 px | 140 px | 220 px |
| 弹开时长 | 0.40 s | 0.50 s | 0.32 s |
| 过冲 | 12% | 8% | 18% |
| 压扁 | 1.25/0.75 | 1.15/0.85 | 1.35/0.65 |
| 回弹次数 | 3 | 2 | 4 |
| 镜头抖动 | 2.5 px | 1.5 px | 4 px |

默认 1.0；制作人试看后可整体乘 0.7 或 1.3。

### 验收标准（动手前写 qc.py）

1. 两身体独立走神；未控制增长、切换停止、持续控制缓慢恢复、切走不重置（stage53）；
2. 未满时速度/氧气/碰撞/输入不变（stage53）；
3. 满值 0.65 s 预兆，切回可取消；后果只取连击损失或 ≤0.5 s 减速之一（stage53）；
4. 兔子两个动作、乌龟两个动作，无正收益、无扣氧/事故（stage53 + 截图）；
5. Q 弹无瞬移：压扁、160–200 px/0.35–0.45 s、2–3 次回弹；6 次 `BONK_OUT`（stage45）；
6. 全关 53/53、无卡死、`best.json` 不变（stage3_playtest）。

## 13. 风险与禁止

风险：

- 走神太快 → 烦；太慢 → 没感觉；从中压力档开始；
- 动作池抢戏 → 本轮只 4 个动作；
- Q 弹太强 → 晕/挡视线；默认 1.0，可乘 0.7；
- 两套压力并行 → 替换旧 MISCHIEF，不并行；
- 没有真人试玩 → 先给截图/录屏和探针数据，不冒充手感结论。

禁止：

- 新按键、新敌人、新障碍、新环境系统；
- 改下潜规则、氧气阈值、障碍数据；
- 强制切换、锁输入、改碰撞/逻辑位置；
- 额外计分体系、恢复 0/3 面板；
- 把走神度做成必须一直盯的 HUD 计时任务。
