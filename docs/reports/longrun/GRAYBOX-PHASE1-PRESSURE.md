# 灰盒 Phase 1 · 切换压力与 MISCHIEF 2.0

- 基线：FEEL-49
- 范围：只做机制/反馈，不加美术、音频、新按键、新敌人。
- 未导出、未打包、未覆盖 Web/EXE；`best.json` 已恢复基线。
- 终点海滩 + 大表哥不在本轮，按修订计划放入 Phase 2。

## 1. 为什么要改

旧版 MISCHIEF 的实际触发概率很低：

- 失误后抱怨窗口只有 2.6 s；
- 还要离下一个障碍 700 px 以上；
- 仍有 32% 概率被忽略；
- 兔子动作在乌龟不潜/不跃时永远是“拽绳”；
- 拽绳只加 `imbalance(0.10)` + `start_flip()`，没有改变速度/深度。

所以玩家几乎只看到拽绳，几乎看不到“电对方”。这不是表现问题，是机制问题。

## 2. 本轮改动

### 2.1 触发

- 抱怨窗口 2.6 → **7 s**；
- 给玩家 **1.2 s** 的“我把谁留失控了”反应时间；
- 去掉 32% 随机抑制：满足条件就触发；
- 安全距离 700 → **520 px**；
- 预兆 0.45 → **0.65 s**；
- 冷却 1.8 → **3.0 s**；
- 预兆时头顶显示动作标签：`拽绳 / 电击`，不再让玩家猜。

### 2.2 动作池和真实后果

| 失控者 | 玩家状态 | 动作 | 真实后果 |
|---|---|---|---|
| 兔子 | 乌龟下潜/跃起 | 电击 | 取消跃起/打断下潜，0.35 s 不能下潜，速度 ×0.8 |
| 兔子 | 乌龟巡航 | 电击/拽绳交替 | 第一次电击；之后按序列在电击和拽绳间交替 |
| 兔子 | 乌龟巡航 + 拽绳 | 拽绳 | `tug_t=0.65`：目标速度 ×0.72，目标深度 +28 px |
| 乌龟 | 兔子空中 | 电落 | 兔子被向下电落 |
| 乌龟 | 兔子在壳上 | 电击 | 失衡更深，前冲更明显 |

乌龟新增两个状态：

- `tug_t`：真实减速 + 壳下沉；
- `zap_stun_t`：短时间禁止下潜。

不是只翻肚皮。

### 2.3 电击可见性

兔子使坏动作按角色序列交替：偶数次必定电击，奇数次在乌龟不潜/不跃时拽绳。
这样一局里会同时看到两种动作，不会全部退化成拽绳。

## 3. S 等级与结算/失败页

### S 等级

- **S：0 事故 + 8000 分**
- A：1–2 次事故
- B：3–5 次事故
- C/D：更多或低分

stage3 自动跑 5 次事故，现在结算为 **B**，不再是 S。

### 结算页

- 保留时间/失误/干净通过/最佳；
- 非 S 时显示下一目标：
  - 有事故：“下一目标：S 需要 0 次失误（本局 N 次）”
  - 无事故但分数不足：“下一目标：S 需要 8000 分以上”
- 不增加练习模式/幽灵回放（按制作人决定不做）。

### 失败页

- 增加明确原因：“原因：氧气耗尽”；
- 增加可执行建议：“先 SHIFT 乌龟上浮，或让兔子吃海藻补氧”；
- 保留再来一次/回主菜单；
- 不引用练习模式/幽灵。

### 全关 MISCHIEF 观测

- 在未关闭 MISCHIEF 的 stage3 试跑中，一局记录 **7 次动作**：
  - `rabbit_shock` 3 次；
  - `tug` 2 次；
  - 其他 2 次（含 priority/shift 中断）。
- 该试跑同时出现一次 `bird6` 普通障碍接触，固定驾驶器不处理捣乱造成的时序偏移；
  因此正式 `stage3_playtest` 在**关卡回归**中关闭 MISCHIEF，MISCHIEF 由
  `stage15_mischief` 单独覆盖。两者合起来才是完整验证。
