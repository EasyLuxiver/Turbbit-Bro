## 1. 6 组新增动态障碍（7/55 → 13/55）

浪涌浮木 y −18±22 / 5.0 s），所以 E2 已经扫过的相位表对新组同样成立。
选组标准只有一条：**不是食物锚点**（9 个锚点在 E 段定死），
否则会动到零食刷新点。

|---|---|---|---|---|
| rock4 | 2 | SURFACE_ROCK | 潮汐 ±52 / 3.6 s | 进 Z2 第一组岩，让“进新区就看得见东西在动” |
| log2 | 2 | FLOATING_LOG | 浪涌 −18±22 / 5.0 s | Z2 中段补浪涌，三原型在 Z2 内都出现一次 |
| rock7 | 2 | SURFACE_ROCK | 潮汐 ±52 / 3.6 s | Z2 后段，和 rock4 拉成“进区/出区各一块潮汐岩” |
| shark6 | 3 | SHARK | 巡游 ±30 / 4.5 s | Z3 第一只鲨，Z3 开头不再全是静的 |
| rock11 | 3 | SURFACE_ROCK | 潮汐 ±52 / 3.6 s | Z3 中后段（宽度 150，本来就比同区宽 30 px） |
| rock12 | 3 | SURFACE_ROCK | 潮汐 ±52 / 3.6 s | 终点前最后一组，全程最后一跳在浪里收尾 |

改后分布：

| | Sunny Coast | Coral Chaos | Muscle Mayhem | 合计 |
|---|---|---|---|---|
| 动态（G 段后） | 1/12（8.3%） | 6/19（31.6%） | 6/24（25.0%） | 13/55（23.6%） |

读法：Z1 保持 1 组是故意的——教学区不叠加变量；Z2/Z3 每约 3 组里有一组会动，
但同一组内最多只有一个自由度（要么 y 要么 x），不出现“两轴同时动”的读不出来的情况。

## 2. E2 探针扩到 13 组：规格与位移全部对表

`stage5_e2_motion` 的 GROUPS 从 7 组扩到 13 组，扫法与 E2 完全相同：
岩 8 个相位、鲨 8 个相位、浮木 5 个相位。

| 检查项 | 结果（13/13 组） |
|---|---|
| `amp_measured` = 规格值 | 52.0 / 30.0 / 22.0，全等 |
| `period_repeat_delta` = 0 | 3.6 / 4.5 / 5.0 s，全为 0 |
| `range_measured` | 岩 [−52, 52]、鲨 [−30, 30]、浮木 [−40, 4]（= −18±22） |
| `rect_follows_offset` | 13/13 true（碰撞矩形跟着画面走，不是只动贴图） |
| `no_cross_axis` | 13/13 true（y 的组 x 不动，反之亦然） |
| 越障扫描命中 | 岩 7 组 × 8 相位 = 0 次；鲨 3 组 × 8 相位 = 0 次；log2 5 相位 = 0 次 |

最后一行是给自动驾驶兜底用的：探针按“标准时机跳/跃/潜”逐一踩相位，
0 命中说明新组没有变成“相位不对就一定撞”的陷阱。
探针输出：`E2 MOTION: PASS`；数据 `docs/reports/longrun/rebuild05-e2-motion.json`（04:10 重跑）。

## 3. 被否掉的设计：按“差点擦过”给正反馈

想法：玩家贴着障碍边缘过 → 给额外分/特效（类似“险过”奖励）。
动手前先量了真实余量，量完发现这个机制会**在几乎每次正常通过时触发**。

`stage5_g_measure` 对每组障碍扫描起跳提前量（岩：20–120 px 步长 10）和
落点偏移（鲨：−60–60 px 步长 20），记录角色矩形与障碍矩形的最小间距：

| 组 | 干净通过的余量 | 结论 |
|---|---|---|
| rock1（静） | 起跳提前 80 px 时余量 28.8 px；更早/更晚都会收窄 | 标准跳的容错窗只有 ±30 px 量级 |
| rock3/rock4/rock7/rock9/rock11/rock12 | 最优余量 28–37 px；提前量偏离最优 ±30 px 就掉到 <10 px | 同上，且动组的窗口还会被相位切走 |
| shark1/3/5/6 | 最优余量 18–26 px，且**标准跃起（shift=0）在 shark3/5 上余量为负（命中）** | 鲨鱼必须提前跃，标准时机本身就在边缘 |
| shark8/shark9 | 当前种子（20261112）已被抽签改画成 SURFACE_ROCK，鲨鱼扫描数字无意义 | 不作为判断依据 |

结论：**在现有几何下，“余量小于 X px”不是玩家本事的度量，而是障碍本身的固定间隙**。
按绝对阈值判定，会在全绿的两圈里几乎每一跳都判成“险过”，奖励就不再有信息量；
反过来把阈值压低，又只会让少数抽签相位偶然触发。
所以这个机制不接入，只保留测量探针与 `rebuild05-g-margins.json` 作为“为什么不做”的证据。
（探针的可复用价值在于：以后要调障碍尺寸/跳高，先跑它看余量分布。）
