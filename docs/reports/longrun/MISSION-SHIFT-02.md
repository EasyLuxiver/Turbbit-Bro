# TURBBIT BRO! — SHIFT CORE & CHARACTER PERSONALITY REWORK

任务编号：TBB-SHIFT-CORE-02

当前阶段：STAGE 4。

本轮目标：让 SHIFT 从一个单纯的控制权切换功能，变成真正有压力、有角色性格、有操作价值的核心玩法。

不得进入 STAGE 5。

## 1. 核心设计方向变更

此前规则解决了未受控制角色自动下沉、滑落的问题，但同时让角色待命变得过于安全。

现在正式调整：

**未被控制的角色可以神游，并且必须对游戏产生实际影响。**

但不能简单恢复成：
- 不控制乌龟就持续下沉。
- 不控制兔子就持续滑落。
- 倒计时结束直接增加 BRO METER。

新的设计是：角色有自己的性格，会因为没有受到控制而逐渐分心，产生可见行为和实际麻烦。

## 2. 建立 BRO BRAIN 神游机制

建立一个统一、可理解的角色神游系统。

暂定内部状态：
- CALM
- DISTRACTED
- RESTLESS
- MISCHIEF

初始时间测试基线：
- 0–3秒：正常待命。
- 3–6秒：开始分心。
- 6–9秒：产生明显行为干扰。
- 9秒以后：进入明显的恶作剧状态。

时间只是调试基线，不是固定事故倒计时。

### 兔子未被控制时

根据状态逐渐表现为：
- 正常站姿。
- 摆姿势、展示肌肉。
- 重心晃动、脚步错乱。
- 靠近龟壳边缘、抓稳动作明显。
- 临界失衡，需要重新接管。

兔子不能只因未受控制就必然掉水。

神游状态必须影响后续操作和碰撞风险，让玩家有理由重新控制兔子。

### 乌龟未被控制时

根据状态逐渐表现为：
- 正常巡航。
- 嗅食物、左右张望。
- 轻微上下晃动、注意力分散。
- 对食物表现出强烈兴趣。
- 可能在遇到食物时主动做出明显的进食动作。

禁止简单恢复成待命持续下沉。

乌龟神游需要影响其后续巡航和动作准备，使玩家有理由切换回乌龟。

### 神游恢复

- SHIFT立即取得控制权。
- 取得控制权不等于立即清空神游。
- 当前受控角色通过稳定操作逐渐恢复。
- 再次切换走时，未恢复的神游程度保留。
- 快速SHIFT不能白嫖恢复。
- 不设置三秒输入锁。

神游是行为干扰，不是第二套生命系统。

不得与BRO METER形成重复惩罚。

## 3. 食物机制与神游整合

修复当前控制兔子时乌龟无法吃到加速食物的问题。

食物触发必须依据乌龟的真实物理位置和碰撞，而不是当前活动角色。

正式规则：
- 乌龟实际接触食物就能吃到。
- 无论当前控制兔子还是乌龟，都能正常触发。
- 吃到食物后，乌龟的饥饿、烦躁和神游状态明显恢复。
- 给予短暂1.15倍加速。
- 不允许无限叠加。
- 加速期间碰撞和操作仍然可靠。
- 食物效果结束后平滑恢复正常巡航。

如果乌龟处于受控状态，可以利用正常上下动作决定是否接触食物。

吃到食物不自动算作普通障碍通过，也不重复发放分数。

## 4. 海鸟障碍重新设计

目前海鸟可以被兔子跳、兔子趴、乌龟跃、乌龟潜全部轻松躲过，缺乏明确操作意义。

重新设计成动态的低空俯冲威胁：
- 先出现飞行预警。
- 展示攻击方向。
- 进入龟壳上方的低空攻击区域。
- 有清晰的攻击和退出过程。

兔子趴低是主要推荐路线。

其他动作可以作为替代解法，但不能与主解法完全等价、同样无风险。

优先通过飞行轨迹、攻击时机和合理空间设计完成，不允许随意扩大碰撞盒制造强制失败。

每种路线要记录：
- 成功率。
- 反应窗口。
- 是否碰撞。
- 是否保持干净通过。
- 是否影响后续操作。

如果海鸟在当前空间里不适合做这种障碍，就重新设计为真正合理的水面威胁，不保留无意义的障碍类别。

## 5. BRO DIVE 优化

当前BRO OLLIE成功，但BRO DIVE的实际操作体验明显偏难。

重点检查：
- 兔子起跳时机。
- SHIFT交接。
- 乌龟下潜起始窗口。
- 兔子空中轨迹。
- 漂浮木上、下通道的真实空间。
- 乌龟通过障碍的时间。
- 兔子重新落脚位置。
- 接人判定。

不得通过单纯降低自动驾驶速度掩盖问题。

调整目标：
- 首次可见预警至少满足既定组合障碍目标。
- 关键操作窗口不要求单帧精确输入。
- 兔子跳跃与乌龟下潜真实并行。
- 玩家有足够的纠错空间。
- 连接过程自然，不出现意外瞬移。

## 6. 兔子落水位置与救援物理

修复兔子落水后瞬间出现在乌龟前方的问题。

要求：
- 兔子从实际离开龟壳的位置落下。
- 保留世界坐标、重力和运动方向。
- 水花发生在实际落点。
- 不允许为了方便接人而直接设置到乌龟前方。
- 区分真实落水、主动救援和事故后的安全恢复。

建立可靠的接人判定：
- 检查相对位置和速度。
- 合理扩大龟壳附近的有效接人区域。
- 增加短暂接人容错窗口。
- 只在真实靠近时允许轻微吸附。
- 成功接人必须有清楚反馈。
- 失败必须记录实际原因。

优先保留玩家主动切换和控制的作用，不允许以自动瞬移代替接人。

## 7. BRO DIVE 与接人验收

- 不同兔子落点。
- 不同游戏帧率下的接人。

不允许只测试一个固定完美时间序列。
