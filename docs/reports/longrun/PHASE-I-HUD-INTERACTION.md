## 0. 一句话结论

HUD 的占屏、布局、优先级本来就达标；这一轮真正找到并修掉的是**对比度**——
压在 60% 面板上的灰色字、红色字在亮天空下只有 3.6–4.2:1。改的是文字色，
面板透明度没动（验收标准 3 判的就是 60% 这个口径）。

| 项 | 改前 | 改后 |
|---|---|---|
| `MUTED`（区域 / 进度 / 教学行） | 3.81:1 | **5.25:1** |
| `RED` 当作文字用（BRO METER / 缺氧 / hit 反馈） | 3.59:1（亮面板）/ 4.11:1（底部） | **4.96:1 / 5.35:1** |

| 失衡档位 ≥80% | 3.59:1 | **4.96:1** |

最差一条从 3.06 提到 4.76（25–50% 的 AMBER）。全表见 §3。

## 1. 改了什么（一处文件，只有颜色）

`scripts/ui/hud.gd`

```gdscript
const MUTED := Color(0.78, 0.88, 0.95)      # was (0.62, 0.76, 0.86)
const RED := Color(1.0, 0.36, 0.3)          # 不动：槽条 / 分格继续用饱和红
const RED_TEXT := Color(1.0, 0.80, 0.72)    # 新增：压面板的红字用这一档
```

- `_risk_color()` 四档换成在亮面板上够亮的版本（`RED_TEXT` / `(1.0,0.80,0.55)` / `AMBER` / `(0.66,0.86,1.0)`）。
- `_feedback_color("hit")`、`bro_meter_label`、`oxygen_status` 的红字分支改用 `RED_TEXT`。
- `PANEL_BG` **没有改**，仍是 `Color(0.02, 0.07, 0.1, 0.6)`。

为什么不把面板调暗：要压到 5:1 需要 alpha ≈0.9，那就是任务书里明令避免的“大块不透明面板”。
亮天空 + 半透明的组合下，唯一出路是把字提亮。

没动布局：占屏 4.17%（中）/ 5.28%（英）本来就在 8% 以内，再缩会牺牲可读性。

重要事实：项目是 `window/stretch/mode="canvas_items"` + 1600×900 逻辑视口。
1280×720 下逻辑视口**仍然是 1600×900**，画面等比缩到 0.8——所以布局不可能因为缩窗口而截断，
但也意味着 15 px 的行在 720p 上实际只有 12 px。这一条记在 §5 的已知限制里。

四张图都看过：无截断、无面板重叠、底部中央不压左右两块面板。

## 5. 已知限制（如实记）

1. **输入注入不是 OS 级。** 菜单/暂停/结算测试把 `InputEventMouseButton` /
   `InputEventKey` 直接 `push_input` 到真实窗口的根视口（日志里 `viewport (1600,900)` 可证是真窗口，
   不是 headless 的 64×64）。这不等于用真鼠标点、用真键盘按。
   本机 OS 级 `SendInput` 此前实测被系统拒绝（见 `race.gd:1784` 注释），本轮没有再试。
2. **1280×720 的文字有效尺寸是 12 px。** 布局不截断，但小窗口下看久了会累。
   要不要为 720p 单独抬字号，属于产品判断，本轮没动。
3. **底部中央的文字直接压在画面上**（没有面板，免得挡角色）。实测最坏背景是沙地 (0.34,0.28,0.20)，
   最差 6.55:1，够用；但如果以后加了更亮的场景，这条会先掉下去。
4. 实测的是**一帧静态画面**的最亮背景。障碍物（高墙立柱）正好压在字下面时背景会更暗，只会让比值更高，
   不会更低——所以取最亮是保守的。
