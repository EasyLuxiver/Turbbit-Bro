## 1. 海鸟行为选择：从固定实例到遭遇级

### 修改前

- FEEL-19 用 `extra := {bird3:poop, bird4:chase, bird6:return, bird8:poop}`，行为绑定到实例名。
- bird8 被食物抽签替换成 SURFACE_ROCK 后不会触发鸟行为；不同种子下也没有行为组合变化。

### 修改后

- `_init_bird_behaviors()` 改为按**当前存在的 LOW_BIRD 遭遇**生成计划：
  - 合法序列池：`dive`、`dive+return`、`poop+dive`、`chase+dive`、`poop+return`、`dive+chase`；
  - 第一只鸟强制普通俯冲（教学遭遇，不给额外攻击）；
  - 之后最多 3 个额外行为遭遇，避免全群变招；
  - 同种子可复现（`RandomNumberGenerator.seed = level_seed ^ 0x51A7`）；
  - 特殊序列不连续重复（纯俯冲是默认，不参与“特殊组合重复”约束）。
- 每个状态保存 `queue/idx/mode/phase/t/target`，不再是单一固定 mode。
- 序列执行：`WAIT → TELEGRAPH 0.55 → ACTION 0.65 → RECOVER 0.55 → NEXT 0.45 → 下一动作/DONE`。
- 目标在**遭遇开始时**按 TUBO/BITT 实际位置锁定；投射物/鸟体使用固定目标，不会中途追着旧控制者改目标。
- bird8 若被抽签替换，该组不再是 LOW_BIRD，因此不会创建鸟计划；这是“该遭遇没有鸟”，不是行为丢失。

### 行为实际变化

| 遭遇 | 可选行为 | 说明 |
|---|---|---|
| 任意海鸟 | 普通俯冲 | 静态 A 带 + 原 bird_pose，不变 |
| 额外遭遇 1–3 | 回马枪/排泄/追逐组合 | 每次遭遇 1–2 个动作；目标按位置 |
| 后续海鸟 | 普通俯冲 | 限制总数，防止全群同时变招 |
| bird8 被替换 | 无鸟 | 食物抽签改变的是种类，不是鸟行为系统丢失 |

### 验证

- `stage19_bird_behavior` **17/17**：
  - 三种额外行为的 TELEGRAPH/ACTION/RECOVER；
  - poop 命中 TUBO/BITT；
  - 回马枪/追逐鸟体命中对应角色；
  - 电弧抵消；
  - 30/60/120 Hz；
  - 同种子计划一致、不同种子改变、特殊序列不连续重复。
- 截图：`feel19/bird-poop-telegraph.png`、`bird-poop-projectile.png`（FEEL-19 已有，本轮未重新截图）。

## 2. P1：55 组连续情境改造

### 2.1 G10–G17：海鸟骚扰 + 梁/组合

**改造前**：G10 gate2→G11 bird2→G12 beam1→G13 shark3→G14 beam3→G15 rock4→G16 gate3→G17 bird3，共 8 组单角色；鸟没有额外攻击，G11/G17 只是普通俯冲。

**改造后**：
- 海鸟计划的第一只鸟保持普通俯冲（G1），之后前 3 个额外行为遭遇落在 **G11（bird2）**、**G17（bird3）**、G24（bird4）。
- G11 额外行为可能是 poop/return/chase 组合，结束后 4.69 s 到 G12 beam1；G17 额外行为后 5.27 s 到 G18 log2。
- 玩家在 G11 先读海鸟预兆/目标，再用 TUBO 处理 G12 低梁；G17 后要准备 G18 的 TUBO 跳→SHIFT→BITT 潜。

**决策**：
- G11：鸟攻击目标是谁？TUBO 趴低还是 BITT 下潜；之后是否提前保持 TUBO 处理 G12。
- G17：鸟攻击后是否提前切到 TUBO，给 G18 的 BRO DIVE 留出起跳。
- 普通玩家：G11/G17 仍可只躲/等，G12/G18 按原路线过。
- 熟练：把鸟攻击当作“换人理由”，提前把下一组需要的角色放好。

**风险/反应**：
- G11→G12 4.69 s；G17→G18 5.27 s，足够；不靠缩短间距制造难度。
- 鸟目标锁定，不会切角色后追踪旧目标。

### 2.2 G31–G35：Z3 入口角色交替

**改造前**：gate5(B)→shark6(B)→beam6(T)→rock8(T)→gate6(B)，B/B/T/T/B，两个连续 B、两个连续 T。

**改造后**：把 `beam6` 与 `shark6` 在原有 x 槽位交换：
`gate5(B)→beam6(T)→shark6(B)→rock8(T)→gate6(B)`。
x 不扩展，只换顺序；shark6 仍是水下伏击。

**决策**：
- gate5 后是否提前切 TUBO；beam6 后是否切 BITT 处理 shark6；rock8 再切 TUBO；gate6 再切 BITT。
- 普通玩家仍可按当前角色逐组处理；熟练玩家可用“提前切”减少 0.2 s 锁。
- G31→G35 的间距 3.75–3.95 s，保留呼吸但形成连续 B/T/B/T/B。

**风险**：
- 角色切换频率上升，需要真人确认是否手忙脚乱；全量 audit/两圈必须过。

### 2.3 G39–G41：保留连续三拍，未强改

**现状**：beam7(T)→rock9(T)→gate7(B)，间距 3.75/3.85/3.95 s。
- 这已经是“连续三拍”，但 T/T 两连；本轮没有为了双角色比例强行交换 gate7（600 宽长隧道，前移会把间距压到 2 s 以下）。
- 保留原结构；建议下一批只做**间距级**调整，不碰 gate7 的 600 宽长隧道。

### 2.4 改造后的决策密度

- G10–G17：从 8 组纯单角色 → 2 个海鸟额外行为 + 原有梁/岩/闸门；玩家至少做 2 次“看鸟→选角色”。
- G31–G35：从 B/B/T/T/B → B/T/B/T/B，角色切换点从 2 个增至 4 个。
- G39–G41：未改，保留原三拍；不宣称已完成。

## 3. 海鸟攻击公平性检查

| 检查 | 结果 |
|---|---|
| 预兆 | TELEGRAPH 0.55 s；高空 `!`/落点线/投射物落点圈 |
| 反应时间 | 0.55 s 预兆 + 攻击前摇；30/60/120 的启动时间 0.56–0.60 s，帧率不改变语义 |
| 攻击对象 | 遭遇开始时按实际横向距离锁定；同一 encounter 不切换 |
| 切换角色后 | 目标不追踪旧角色；投射物落点保持锁定 |
| 与相邻障碍重叠 | 全量 audit no_solution 见第 6 节；G11/G17 与下一组 4.69/5.27 s，有呼吸 |
| 落点与碰撞一致 | 画/判共用 `_bird_attack_rect()`；poop 24×24，鸟体 120×44 |
| 电弧抵消 | 只在 MISCHIEF shock ACTION 窗口；只对 poop；抵消后移除攻击体，无残留 |

**自动驾驶事故**：两圈各 1 次事故（FEEL-19 之前 0）；这是自动驾驶没有适配鸟攻击，不是玩家无解。真人窗口需试玩确认。

## 4. P2：鲨鱼群最小可行方案（未接入）

现状：每组鲨鱼是一个完整身体矩形 + 单条 `_ambush` 状态；不存在“领头/跟随”的合法性基础。

最小方案（不新增组、不新增类型）：

```
CIRCLE
  → LEAD_TELEGRAPH 0.55 s（领头有预兆）
  → LEAD_LUNGE 0.65 s（现有身体矩形判定）
  → COMPANION_1（错开 ≥0.45 s，只在该窗口有独立矩形）
  → COMPANION_2（再错开 ≥0.45 s）
  → RETREAT / COOL
```

- 领头承担主要攻击判定；跟随鲨鱼只在各自的明确窗口参与，其余时间不覆盖水域。
- 伙伴视觉可在领头上/下偏移，用现有鲨鱼绘制；不新增鲨鱼种类。
- 同一时间最多 1 个攻击体；不允许群体矩形覆盖整条水域。
- 与 BITT 下潜/TUBO 落水/救援/氧气：伙伴攻击不进入水下救援状态；救援优先级高于一切鲨鱼攻击。
- 需要新的 `_shark_attacks` 数组/状态和绘制，风险高于本轮鸟行为；**本轮只给方案，不开发**，等待制作人批准。
